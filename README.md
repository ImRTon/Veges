# 台北蔬果價

台北蔬果價（Veges）是一個以台北家庭採買為場景的 Android App。它把官方批發市場資料整理成容易比較的行情、參考估算與價格方向，讓使用者快速回答：

> 我常買的蔬果現在大約多少錢？價格有沒有變化到值得注意？

App 把官方批發行情、台北市場估算、價格變化和天候資訊放在同一個脈絡中，讓你快速看懂今天的價格與接下來值得注意的變化。

## 功能

- **行情首頁**：查看追蹤品項、價格變化與市場整體漲價訊號；也會顯示通過官方天候警示判定的產區供應風險。
- **蔬菜與水果市場**：用日常名稱搜尋，依視覺化分類瀏覽，透過代表性插圖辨認品項。
- **品項詳情**：查看台北合併、台北一或台北二的資料基礎、參考估算、資料日期、個別價格方向與歷史行情。
- **7–14 日方向雷達**：以近期價格、成交量與官方天候訊號判斷「價格轉強」、「價格轉弱」或「目前方向不明」。
- **追蹤與價格提醒**：將常買品項加入清單，設定低於某個「參考估算」時的本機通知門檻。
- **離線優先**：保留本機快取與追蹤設定；更新失敗時繼續顯示可用資料，並標示資料較舊或離線狀態。

## 資料與估算

### 資料來源

- [農業部農產品交易行情](https://data.gov.tw/dataset/8066)：每日批發交易資料，包含平均價、上下價與交易量。
- [農業部作物目錄](https://data.moa.gov.tw/api/v1/CropType)：官方品項對照。
- [臺北市公有零售市場行情](https://data.taipei/dataset/detail?id=54d9d492-1e2e-40d1-ae7b-fbce6f271bf1)：歷史零售資料，用於模型校準與資料審查。
- [交通部中央氣象署開放資料](https://opendata.cwa.gov.tw/)：產區天候風險訊號。

### 台北市場基礎

預設顯示「台北合併」，由台北一與台北二同日的有效批發資料依成交量加權；進階使用者可以切換至單一市場。原始批發資料以元／公斤提供，畫面依家庭採買習慣換算並標示元／台斤。

「市場參考」採用經審查、具版本與 checksum 的參考模型：

```text
批發平均價（元／公斤）× 0.6 公斤／台斤 × 2.0
```

### 價格方向與圖表

- 市場整體雷達綜合價格與到貨量等市場證據；天候警示作為供應風險背景。
- 品項雷達比較近期有效交易日與較長期基準，輸出 7–14 日的方向、幅度與可讀的證據。
- 價格歷史圖採用蔬果市場區間 K 線：線體連接前一日與當日平均價，影線代表官方高低價，成交量另列為觀測資料。
- 休市、缺值、零值或不完整資料不會被當成零元行情；App 會保留最後有效快取並標示狀態。

## 設計理念

### 先回答採買決策

畫面優先呈現品項名稱、價格、單位、日期、變化與下一步操作。首頁適合快速掃描，詳情頁才展開來源、方法、歷史和方向證據。

### 把不確定性做成產品資訊

不同資訊各自回答不同問題：批發觀測反映市場成交，市場參考估算方便家庭比較，7–14 日方向與產區風險提示值得留意的變化。來源市場、資料日期與估算標籤都在適當位置呈現。

### 日常名稱優先，官方資料可追溯

使用者先看到「高麗菜」等日常名稱；官方品項只作為必要的資料脈絡。別名有歧義時讓使用者選擇，不用靜默猜測，以免把相似品項的價格混在一起。

### 金融產品的清晰度，不使用金融話術

借用行情 App 的價格層級、快速掃描、趨勢圖與自選清單，但不複製投資產品的品牌語言，也不把蔬果價格包裝成投資建議。漲跌同時使用文字、符號與色彩，不靠顏色單獨傳達意義。

### 插圖幫助辨識，不冒充實物照片

目錄插圖用來辨認品項，不代表實際商品、產地、等級、包裝或品質。插圖是經審查的 AI 生成示意圖，App 以「AI 生成示意圖，非實物照片。」揭露其用途。

## 技術架構

專案採 Kotlin 多模組架構，UI、領域邏輯、資料存取與發行工具分離：

| 模組 | 職責 |
| --- | --- |
| `app` | Android 入口、導覽、依賴注入與整合測試 |
| `home` | 行情首頁、追蹤清單、漲跌與產區風險雷達 |
| `catalog` | 蔬菜／水果目錄、搜尋、分類與歧義選擇 |
| `detail` | 品項詳情、參考估算、方向雷達與價格歷史 |
| `alerts` | 價格提醒規則與通知權限狀態 |
| `design-system` | Material 3 主題、價格格式、狀態與揭露元件 |
| `domain` | 純 Kotlin 領域模型、估算、趨勢、預測與提醒規則 |
| `data` | Room 快取、官方 HTTP client、目錄匯入、同步與 WorkManager |
| `release-tool` | 目錄、來源快照、模型 artifact、checksum 與歷史審查 |

主要技術：Kotlin、Jetpack Compose、Material 3、Hilt、Room、Retrofit／OkHttp、WorkManager、Kotlin Serialization；Android minSdk 26、compileSdk 36、JVM 17。

資料流遵循「來源 → 驗證 → 本機快取 → 領域計算 → UI」：

1. `data` 從官方 HTTPS 來源取得並驗證欄位、單位、日期、休市訊號與市場。
2. 有效資料以 Room 原子保存，讓畫面可在離線時使用上一份完整快取。
3. `domain` 只使用有效觀測與審查過的目錄／模型 artifact 計算估算、方向和提醒。
4. Compose 畫面顯示結果及其來源日期、資料狀態和必要的方法說明。

App 沒有帳號、雲端資料庫、廣告、分析 SDK 或自有後端。追蹤品項、提醒規則、估算與通知紀錄留在裝置；網路請求直接連到設定的官方資料來源。

## 建置與測試

### 環境

- Android Studio
- JDK 17
- Android SDK 36
- Windows 可直接使用 repository 內的 `gradlew.bat`

天候風險需要中央氣象署 API key。將它放在本機 `local.properties` 或 Gradle property 的 `CWA_API_KEY`；不要提交到 Git。沒有天候 key 時，其他行情與本機功能仍應可編譯與測試。

### 常用指令

```powershell
# 編譯 Debug
.\gradlew.bat :app:assembleDebug

# 執行 JVM 單元測試
.\gradlew.bat test

# 執行格式、Lint 與測試驗證
.\gradlew.bat verifyFormatting staticAnalysis test

# 建立並驗證 Release APK
.\gradlew.bat --dependency-verification=strict verifyFormatting staticAnalysis test :app:validateReleaseArtifact
```

Android instrumentation tests 需要連接的 emulator 或實機；完整發行流程與線上／離線／休市／通知權限矩陣見 [RELEASE_RUNBOOK.md](RELEASE_RUNBOOK.md)。
